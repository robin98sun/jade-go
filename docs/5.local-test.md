# Local test

1. generate environment variable files for each node
    ```bash
    # Example:
    # ./devops/speed-env.sh \
    #  ./devops/deployments/local-test \  # location to store env files
    #  cluster-1                       \ # master node name
    #  192.168.57.11                   \ # master node ip
    #  raspberry                       \ # agent node BASE name
    #  2                               \ # agent node count 
    #  192.168.57.13                    # agent node IP start from

    ./devops/speed-env.sh \
      ./devops/deployments/local-test \
      cluster-1                        \
      192.168.57.11                   \
      raspberry                       \
      2                               \
      192.168.57.13

    # then it will generate three files
    # ./devops/deployments/local-test/env_variables-master.txt
    # ./devops/deployments/local-test/env_variables-agent-1.txt
    # ./devops/deployments/local-test/env_variables-agent-2.txt
    ```

1. build jadelet image
   ```bash
   # ./devops/speed-build.sh \  
   #   0.0.520               \ # version
   #   jadelet               \ # name of jadelet
   #   192.168.57.8            # registry

   $ ./devops/speed-build.sh \
       0.0.520               \
       jadelet               \
       192.168.57.8

   ```

1. deploy jadelet onto a cluster, which contains a master node and several agent nodes

   ```bash
   # ./devops/speed-deploy.sh          \
   #    cluster-1                      \  # master node host name
   #    raspberry                      \  # agent node BASE name
   #    2                              \  # agent node number
   #    192.168.57.8/jadelet:0.0.520      # image name

   $ ./devops/speed-deploy.sh          \
        cluster-1                      \
        raspberry                      \
        2                              \
        192.168.57.8/jadelet:0.0.520   

   # this will print all the external ports of each node at the end
   ```

1. test jadelet functions and status
   
   `postman` is recommended, which is a powerful tool for diagnosing interfaces

   The base URL is `http://<node external ip address>:<external service port>`
   
   RESTful interfaces of each pod
   ```bash
   # back door interfaces for debugging          
   GET  /$jade$/debug/jadelet           # see the registration information
   GET  /$jade$/debug/configurations    # see the configurations read from environment variables
   GET  /$jade$/debug/pod               # see pod information
   GET  /$jade$/debug/node?name=raspberry01  # show node information
   GET  /$jade$/debug/subnodes               # show sub-nodes
   GET  /$jade$/debug/capabilityCache        # show capabilities of a node, which is passed in via environment variables
   GET  /$jade$/debug/capacityCache          # show capacity of computing resources of a node
   
   # show a service information, pass name=<service name> as argument
   # example URL arguments:
   # ?namespace=default&name=jade-local-test-raspberry01-service-external
   GET  /$jade$/debug/service           

   # show cluster IP of the pod
   # example URL arguments:
   # ?namespace=default&name=jade-local-test-cluster-1-service-cluster
   GET  /$jade$/debug/clusterIP         

   # show external IP of the pod
   # example URL arguments:
   # ?namespace=default&service=jade-local-test-cluster-1-service-external&node=cluster-1
   GET  /$jade$/debug/externalIP   

   # other useful interfaces

   # update configuration for a node at runtime
   # example POST body: 
   # ./devops/examples/debug/update_configuration.json
   PUT  /$jade$/configurations

   # search node using combinition of capabilities
   # example POST body: 
   # ./devops/examples/debug/search_node.json
   POST /$jade$/debug/searchNodes       

   # Dispatch task
   # example POST body: 
   # ./devops/examples/debug/dispatch_task.json
   POST /$jade$/taskReceiver
   ```
