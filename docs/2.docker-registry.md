# Setup a private Docker registry

## Step 1: Setup Self-Signed SSL Certificate

   1. Create the SSL Certificate 
    
        TLS/SSL works by using a combination of a public certificate and a private key. The SSL key is kept secret on the server. It is used to encrypt content sent to clients. The SSL certificate is publicly shared with anyone requesting the content. It can be used to decrypt the content signed by the associated SSL key.

        We can create a self-signed key and certificate pair with OpenSSL in a single command:
        ```
        sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout ./certs/jade-selfsigned.key -out ./certs/jade-selfsigned.crt
        ```
        You will be asked a series of questions. Before we go over that, let’s take a look at what is happening in the command we are issuing:

            openssl: This is the basic command line tool for creating and managing OpenSSL certificates, keys, and other files.

            req: This subcommand specifies that we want to use X.509 certificate signing request (CSR) management. The “X.509” is a public key infrastructure standard that SSL and TLS adheres to for its key and certificate management. We want to create a new X.509 cert, so we are using this subcommand.
          
            -x509: This further modifies the previous subcommand by telling the utility that we want to make a self-signed certificate instead of generating a certificate signing request, as would normally happen.

            -nodes: This tells OpenSSL to skip the option to secure our certificate with a passphrase. We need Apache to be able to read the file, without user intervention, when the server starts up. A passphrase would prevent this from happening because we would have to enter it after every restart.
          
            -days 365: This option sets the length of time that the certificate will be considered valid. We set it for one year here.
          
            -newkey rsa:2048: This specifies that we want to generate a new certificate and a new key at the same time. We did not create the key that is required to sign the certificate in a previous step, so we need to create it along with the certificate. The rsa:2048 portion tells it to make an RSA key that is 2048 bits long.
          
            -keyout: This line tells OpenSSL where to place the generated private key file that we are creating.
          
            -out: This tells OpenSSL where to place the certificate that we are creating.

        As we stated above, these options will create both a key file and a certificate. We will be asked a few questions about our server in order to embed the information correctly in the certificate.

        Fill out the prompts appropriately. The most important line is the one that requests the Common Name (e.g. server FQDN or YOUR name). You need to enter the domain name associated with your server or, more likely, your server’s public IP address.

   1. Prepare a `.cert` file

        After all the above finished, create a `.cert` file with the same fill-outs:
        ```
        sudo openssl req -new -x509 -text -key ./certs/jade-selfsigned.key -out ./certs/jade-selfsigned.cert
        ```
    
   1. Grant the read privilege for user

        ```bash
        sudo chmod u+r ./certs/*
        ```

   1. Modify Registry server's ssl configuration to support using IP address as certificated name
    
        Provides your IP address is `192.168.57.8`,
        edit the file `/etc/ssl/openssl.cnf` of the server and add `subjectAltName = IP:192.168.57.8` into the `[v3_ca]` section. Like the following:
        ```conf
        ...
        [ v3_ca ]
        subjectAltName = IP:192.168.57.8
        ...
        ```

   1. Copy `.key`, `.crt`, `.crt` files to all client-side machines
    
        provides your server IP address is `192.168.57.8`, and the user created the above files is `rin`, and the above files are located at `~/certs/`

        ```bash
        # on client-side machines
        sudo mkdir -p /etc/docker/certs.d/192.168.57.8

        sudo scp rin@192.168.57.8:~/certs/jade-selfsigned.cert /etc/docker/certs.d/192.168.57.8/client.cert
        
        sudo scp rin@192.168.57.8:~/certs/jade-selfsigned.key /etc/docker/certs.d/192.168.57.8/client.key
        
        sudo scp rin@192.168.57.8:~/certs/jade-selfsigned.crt /etc/docker/certs.d/192.168.57.8/ca.crt

        # on some types of clients, such as Raspbian
        sudo mkdir -p /usr/local/share/ca-certificates
        sudo cp /etc/docker/certs.d/192.168.57.8/ca.crt /usr/local/share/ca-certificates/192.168.57.8.crt
        sudo update-ca-certificates
        sudo systemctl restart docker.service
        sudo reboot
        ```

## Step 2: [Setup a externally-accessible Docker registry](https://docs.docker.com/registry/deploying/)

   On the registry server, start the registry, directing it to use the TLS certificate. This command bind-mounts the certs/ directory into the container at /certs/, and sets environment variables that tell the container where to find the domain.crt and domain.key file. The registry runs on port 443, the default HTTPS port.

   ```bash
    sudo docker run -d \
      --restart=always \
      --name registry \
      -v "$(pwd)"/certs:/certs \
      -e REGISTRY_HTTP_ADDR=0.0.0.0:443 \
      -e REGISTRY_HTTP_TLS_CERTIFICATE=/certs/jade-selfsigned.crt \
      -e REGISTRY_HTTP_TLS_KEY=/certs/jade-selfsigned.key \
      -p 443:443 \
      registry:2
   ```

   check the status of the registry:
   ```bash
   sudo docker ps
   sudo lsof -i -n -P|grep 443
   ```

   if the status of registry container is not `UP` or the port `443` is not under listening, check the container's log
   ```bash
   sudo docker logs registry -f
   ```

## Step 3: Retrieve on private registry

     ```bash
     # List all repositories
     curl -k -L http://192.168.57.8/v2/_catalog

     # List all tags of a repository
     # curl -k -L http://192.168.57.8/v2/<name>/tags/list
     # such as if the repository name is jade
     curl -k -L http://192.168.57.8/v2/jade/tags/list
     ```
