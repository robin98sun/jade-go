
# Setup local test env: Setup a K3S Server and an Agent using VirtualBox
- ## Prerequisits
   1. VirtualBox
   1. Ubuntu Server ISO image and Raspbian Buster ISO image
   1. Recommended minimum Hardware Capacity:
      + 4 Cores of CPU
      + 8 GB onboard memory
      + 20 GB onboard SSD storage
- ## Setup VMs
   1. Create a host-only network in VirtualBox, with DHCP
   1. Setup a Ubuntu Server and a Raspbian using VirtualBox on your laptop, with SSH
      + Assign a NAT adaptor for each VM
      + Assign a bridged network adapter using that previously created host-only network, for each VM 
   1. Setup SSH trust between laptop and VMs
      + SSH to the VM from laptop using the VM's account and password
      + Append the public key of laptop (usually at `~/.ssh/id_rsa.pub`) to VM's file `~/.ssh/authorized_keys`
         - Deploy SSH services (usually `OpenSSH`) on your laptop and these VMs, if they are not installed yet
         - Run `ssh-keygen` in Command Window to create the public and private keys for your laptop and each VM, if they do not have a key yet
   1. You may want VirtualBox tools installed
      - from virtualbox cdrom
         
         1. `Devices > Insert Guest Additions CD image...`
         
         1. `sudo mount /dev/cdrom /media/cdrom`

         1. `sudo apt-get install make gcc linux-headers-$(uname -r)`

         1. `sudo /media/cdrom/VBoxLinuxAdditions.run`

         1. Mount shared folder: `mkdir ~/new; sudo mount -t vboxsf New ~/new`

         1. Authorize user to access shared folder: `sudo adduser $USER vboxsf`

      - or from open packages:
         ```
         sudo apt install virtualbox-guest-dkms
         # for GUI user only:
         # sudo apt install virtualbox-guest-x11
         # then add current user to virtualbox group
         
         # Check your ip and routetable
         netstat -rn
         # to verify or modify settings of network interfaces
         # sudo vi /etc/netplan/00-installer-config.yaml
         # after that to apply the changes
         # sudo netplan apply
         ```
- ## Setup K3S Server and Agent [(reference)](https://rancher.com/docs/k3s/latest/en/advanced/#running-k3d-k3s-in-docker-and-docker-compose)
   1. Uninstall previous installation if needed
      ```
      # K3S server
      /usr/local/bin/k3s-uninstall.sh
      # K3S agent
      /usr/local/bin/k3s-agent-uninstall.sh
      ```
   1. Deploy K3S Server on Ubuntu Server
      + Deploy Docker using command: 
      ```
      curl -fsSL https://get.docker.com | sh -
      ```
      + Let Docker run in user mod using command: 
      ```
      sudo usermod -aG docker ${USER}
      ```
      + Deploy K3S server: 
      ```
      # with an explicit IP address, to avoid using the NAT address, but not stable
      # agents cannot access the server for they are sharing the same NAT IP address
      # But this may cause the installation fail, not stable yet
      # curl -L https://get.k3s.io | sh -s - --docker --write-kubeconfig-mode=644 -—node-external-ip <external IP address>

      # It's recommended to enable NAT, for CoreDNS might be blocked if behinds certain firewall
      # but don't forget to disable NAT after installation
      curl -L https://get.k3s.io | sudo sh -s - --docker --write-kubeconfig-mode 644
      ```
         - external IP address: use the IP Address of the Host-Only network created previously
      + Check K3S service status:
      ```
      sudo systemctl status k3s
      ```
   1. Check the service logs
      ```
      journalctl -u k3s.service -ef
      ```
   1. Modify service startup arguments, just see the service file in the output of `sudo systemctl status k3s`, and modify that file, and reload daemon by `sudo systemctl daemon-reload` and then restart the service `sudo systemctl restart k3s`
   1. Critical IMPORTANT to check DNS service:
         ```
         # Show status of kube-dns pod
         sudo kubectl get pods --namespace=kube-system -l k8s-app=kube-dns
         # Show the log of DNS pod to see if anything is wrong
         sudo kubectl logs --namespace=kube-system -l k8s-app=kube-dns
         ```
   1. ***[Optional]*** Setup K3S Dashboard according to [reference](https://rancher.com/docs/k3s/latest/en/installation/kube-dashboard/)
      +  Prepare account description file
         - `dashboard.admin-user.yaml`
            ```
            apiVersion: v1
            kind: ServiceAccount
            metadata:
               name: admin-user
               namespace: kubernetes-dashboard
            ```
         - `dashboard.admin-user-role.yaml`
            ```
            apiVersion: rbac.authorization.k8s.io/v1
            kind: ClusterRoleBinding
            metadata:
               name: admin-user
            roleRef:
               apiGroup: rbac.authorization.k8s.io
               kind: ClusterRole
               name: cluster-admin
            subjects:
               - kind: ServiceAccount
                 name: admin-user
                 namespace: kubernetes-dashboard
            ```
      +  Deploy Dashboard with remote access:
         ```
         # Remove previous install if needed
         # sudo k3s kubectl delete ns kubernetes-dashboard
         # sudo k3s kubectl create -f dashboard.admin-user.yml -f dashboard.admin-user-role.yml
         
         GITHUB_URL=https://github.com/kubernetes/dashboard/releases
         VERSION_KUBE_DASHBOARD=$(curl -w '%{url_effective}' -I -L -s -S ${GITHUB_URL}/latest -o /dev/null | sed -e 's|.*/||')
         curl https://raw.githubusercontent.com/kubernetes/dashboard/${VERSION_KUBE_DASHBOARD}/aio/deploy/recommended.yaml > dashboard.recommended.yaml
         sudo k3s kubectl apply -f dashboard.recommended.yaml -f dashboard.admin-user.yaml -f dashboard.admin-user-role.yaml

         # Someone behind certain kind of firewall need to download that yaml file manually
         ```
      +  Print the token to access dashboard:
         ```
         sudo k3s kubectl -n kubernetes-dashboard describe secret admin-user-token | grep ^token
         ```
      +  But with exceptions:
         -  for remote access, start a proxy on all interfaces and accept all hosts, such as:
            ```
            sudo k3s kubectl proxy --accept-hosts "^.*$" --address "0.0.0.0"
            ```
         - Kubernetes dashboard does not allow remote access using an address other than `localhost` or `127.0.0.1`. to solve this:
            + setup a ssh link on your laptop:
            ```
            ssh -L <local port>:127.0.0.1:8001 -N <username>@<kubernetes-dashboard-host>
            ```
            + for example using `9999` as local port:
            ```
            ssh -L 9999:127.0.0.1:8001 -N rin@192.168.57.5
            ```
            + access the dashboard using the link:
            ```
            http://localhost:9999/api/v1/namespaces/kubernetes-dashboard/services/https:kubernetes-dashboard:/proxy/#/login
            ```
      +  Save these alias in `.bash_profile` for quick operations
            ```
            alias k3s_dashboard_proxy="sudo k3s kubectl proxy --accept-hosts '^.*\$' --address '0.0.0.0' &"
            alias k3s_dashboard_token="sudo k3s kubectl -n kubernetes-dashboard describe secret admin-user-token | grep ^token"
            alias k3s_node_token="sudo cat /var/lib/rancher/k3s/server/token"
            ```
   1. Deploy K3S Agent on Raspbian
      + Deploy Docker using:
       ```
       sudo apt install docker.io
       sudo usermod -aG docker `whoami`
       ```
      + Obtain K3S server token:
      ```
      sudo cat /var/lib/rancher/k3s/server/token
      ```
      + Deploy K3S agent:
      ```
      curl -sfL https://get.k3s.io | K3S_URL=https://<myserver external IP address>:6443 K3S_TOKEN=<mynodetoken> sh -
      ```
      + Check Agent status:
      ```
      sudo systemctl status k3s-agent
      tail -f /var/log/daemon.log
      ```
   1. For whose network behind certain firewall, [k3s.sh script is available here](./k3s.sh)
- ## Known issues
   1. Debugging DNS: 
      - https://kubernetes.io/docs/tasks/administer-cluster/dns-debugging-resolution/
   1. k3s yaml file write mode:
      - https://github.com/rancher/k3s/issues/389
   1. Expose apps:
      - https://kubernetes.io/docs/concepts/services-networking/connect-applications-service/
   1. Unable to access node from outside
      - related issues
         + https://github.com/rancher/k3s/issues/1958
         + https://github.com/rancher/k3s/issues/1266
         + https://github.com/coreos/flannel/issues/1243
      - solution yet to be tested
         + https://docs.projectcalico.org/getting-started/kubernetes/k3s/quickstart
      - tested workaround
         + disable all the unused network interfaces
         + startup all the newly installed nodes in a cluster, including and from the master, one by one
         + add default gateway using the remaining interface
         + access from outside, after all nodes are started and connected without errors
            * it may has some kind of target network caching mechanism, once setup, can not be updated
